先认识几个词。

分两组记：跟人走的装到你的机器，跟业务走的装到 Repo。

跟人走 · 你的机器

Marketplace部门仓库
一个 Git 仓库，部门共同维护。Plugins、Skills、Instructions、业务 Context 都放在这里，改动走 PR。
PluginAgent Plugin
Copilot 的扩展包，可以打包 Skills、Agents、MCP Servers 和 Hooks。按用途分 common、role、project 三类。
Role你的岗位
api、ios、aos、qa、design 之一。决定启用哪个 role Plugin。
Skill按需加载的能力
一个 SKILL.md 目录。Copilot 遇到相关任务时才读取。可以随 Plugin 提供，也可以单独安装。
Instructions常驻规则
*.instructions.md 文件，Copilot 按 applyTo 自动带进对话。部门级的镜像到 ~/.copilot/instructions/teamai/。

跟业务走 · 当前 Repo

Logical Project业务项目
业务意义上的项目，比如 payments，在 Marketplace 的 manifest/projects.yaml 里声明。一个业务可以横跨多个 Repo。
Physical Project本地 Repo
你本地的一个 Git 工作区。用 projects set 绑定到一个或多个 Logical Project。
Context业务上下文
某个 Logical Project 的 Instructions 和文档。绑定后写入 Repo，Copilot 在这个 Repo 里就懂这块业务。
Learning团队经验
一篇排障或踩坑记录，按 Logical Project 或 shared 归档。用 learning share 提交回 Marketplace。
Project Plugin可选
只有业务需要自己的 Skills 或 MCP 时才有。Marketplace 在 projects.yaml 里用 plugin: 声明，绑定时自动在 Repo 的 .github/copilot/settings.json 启用，不需要手动开关。

只需要记住三个命令。

每个命令只管一个范围。

teamai init
我是谁
你的机器
Marketplace、Role、用户级 Instructions、内置的 teamai Skill。只做一次。
teamai projects set <ids>
这个 Repo 是做什么的
当前 Repo
绑定一个或多个 Logical Project，立即写入对应的业务上下文。
teamai sync
更新到最新
你的机器 + 当前 Repo
刷新 Marketplace，按已声明的状态重新收敛。不会扫描机器上的其他 Repo。

从零到可用。

需要 Node.js 20+、Git，以及 GitHub Copilot CLI（没有时使用 VS Code 作为 fallback）。下面的输出来自真实运行，只做了节选。

安装

目前从源码安装，npm link 后即可全局使用 teamai。

$ git clone https://github.com/teamai-vault/teamai-cli-copilot.git
$ cd teamai-cli-copilot
$ npm install && npm run build && npm link

初始化自己

指定部门 Marketplace 和你的 Role。Plugins 全部安装，只启用 common 和你的 Role。

$ teamai init --marketplace <owner/repo> --role api
Marketplace discovered: teamai
DONE create: ~/.copilot/skills/teamai
DONE plugin-install: common@teamai
DONE plugin-install: api@teamai
DONE plugin-install: ios@teamai
DONE plugin-disable: ios@teamai
...
DONE create: ~/.copilot/instructions/teamai/global.instructions.md

绑定 Repo

进入业务 Repo，告诉 teamai 它属于哪个 Logical Project。内容立即就位，并自动加入 Git exclude。

$ cd payment-service
$ teamai projects set teamai
DONE write: .github/instructions/teamai/teamai/context.instructions.md
DONE write: .teamai/context/teamai/docs/architecture.md
DONE write: .teamai/context/shared/learnings/validation.md
DONE write: .git/info/exclude

路径已缩短为相对 Repo 根目录。

保持最新

团队更新了 Plugins、文档或 Skills 之后，在 Repo 里跑一次 sync。

$ teamai sync
Copilot plugin state is already converged.
Managed user instructions are already converged (2).

它会写到哪里。

teamai 只管理高亮的路径。你自己的 Instructions、Skills 和 Repo 文件保持原样，路径被占用时会拒绝覆盖。

你的机器

  1. ~/.copilot/
  2. skills/teamai/内置 Skill
  3. skills/release-helper/你安装的 Team Skill
  4. instructions/teamai/部门 Instructions 镜像
  5. instructions/my-notes.md你自己的
  6. ~/.teamai/
  7. config.yamlMarketplace、Role、所有权
  8. projects/<repo>/每个 Repo 的绑定

当前 Repo

  1. payment-service/
  2. .github/instructions/teamai/业务 Instructions
  3. .teamai/context/Docs 与 Learnings
  4. .github/copilot/settings.json可选，见 Project Plugin
  5. .github/copilot-instructions.md你自己的
  6. src/你自己的
  7. .git/info/exclude前两个目录不进提交
teamai 管理按需出现不会触碰

把经验还给团队。

分享一条排障经验，或者贡献一个 Skill。teamai 在隔离的 worktree 里完成提交并通过 gh 开 PR，不动你本地的 Marketplace。

本地文件一份 Markdown 或一个 Skill 目录
隔离 worktree独立 clone，不影响当前缓存
分支与提交自动生成分支和提交
Pull Request由 Marketplace 维护者审核
$ teamai learning share note.md
$ teamai skill contribute ./my-skill \
    --owner api-team --target standalone

全部命令。

精确语法以 teamai --help 为准。

设置与 Repo

init [--marketplace <source>] [--role <role>]
配置你自己。只影响你的机器。
role list · role set <role>
查看或切换 Role。
projects list · projects set <ids...>
查看 Logical Project，绑定当前 Repo。
sync
刷新并收敛你的机器和当前 Repo。

Skills

skill list [--tag] [--owner] [--source]
浏览团队 Skill 目录。
skill show <name>
来源、Owner、Tag、本地状态。
skill install <name...> · --tag <tag>
按名字或按 Tag 安装。
skill remove <name...> · tags list
移除已安装的 Skill，查看全部 Tag。

贡献

learning share <file> [--project <id> | --shared]
把经验提交到 Marketplace 的 learnings。
skill contribute <path> --owner <owner> --target <t>
把 Skill 贡献为 standalone 或放进某个 Plugin。

诊断

status
当前状态总览。
doctor
只读诊断。
全局选项 --dry-run 预览所有写入和 Copilot 变更，--version 查看版本。
