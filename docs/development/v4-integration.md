# V4 joint verification

`scripts/smoke-v4-joint.mjs` checks the public CLI against the actual Marketplace resource checkout and its fetched `origin/teamai-learnings` authority. It clones both revisions into a new local source and bare Git remote, then uses public `init`, `sync`, `projects set`, `learning share/pending/retry`, `status`, `doctor`, and `recall`. It never prepares a cache or binding by writing product state directly.

Build first. Put the intended real Copilot launcher on PATH for native runs. On Windows, a private `copilot.cmd` must have its official `copilot.exe` alongside it; both bytes are recorded. Fallback runs require a working real `code` executable and construct a PATH without Copilot, so the production backend selector chooses `FallbackCopilotClient`. This verifies delivery, not VS Code model consumption.

```powershell
node scripts/smoke-v4-joint.mjs --marketplace <absolute-marketplace-checkout> --artifacts <new-absolute-directory> --backend native --root custom
node scripts/smoke-v4-joint.mjs --marketplace <absolute-marketplace-checkout> --artifacts <another-new-directory> --backend fallback --root default
```

`--root` accepts `default` or `custom`; `--backend` accepts `native` or `fallback`. `--cli-root` can select an independently installed package directory instead of the built checkout; `--tarball` records its source artifact hash. Installation/package equivalence is checked separately. `--scenario delivery` omits the repeated contribution fault matrix while retaining authority/Scope/ownership/read-only checks; the default `full` scenario runs the entire chain. Every run requires a new artifact directory, retains all failures, and writes no production source files. Use a task-owned F-drive directory on Windows. The script retains fixtures and evidence for review; cleanup follows the workspace's authorized temporary-file procedure.

Assertions derive from Spec #14: unbound user-only convergence, explicit physical Workspace binding, linked worktree preservation, accurate ownership/root/version, shared/project published and pending Scope, original CRLF payload bytes, authoritative revision/hash/line evidence, durable checkpoints, idempotent lost-response recovery, terminal publication distinctions, neighboring personal file preservation, and read-only/dry-run protection. Each command's argv/stdout/stderr and the real platform/runtime paths are saved in `commands/` and `fixture.json`; `script.mjs` and its recorded raw hash identify the executed script. `result.json`, `seam.jsonl`, and `readonly-protection.json` preserve results and state comparisons, including file content/hash/link count/mtime and Git refs.

Contribution Git operations use a private bare repository through an isolated Git URL rewrite. Only the repository identity read uses a separate isolated configuration without that transport rewrite; the canonical source `.git/config` is independently saved. Fake gh only simulates explicit fault/PR responses and never calls GitHub. Windows runs compile a task-local `gh.exe` argument forwarder with the system .NET Framework C# compiler, record its source/compiler/hash, and verify multiline UTF-8 arguments and separate stdout/stderr before init. The full scenario also checks the exact PR body and destination arguments. Read-only checks disable all Git transport protocols.

Local merge/published checks are state-machine evidence, not a real reviewed external PR or F12/T47 acceptance. Use full native/custom and fallback/default scenarios for both producer paths; the complementary native/default and fallback/custom delivery scenarios check the remaining root/backend combinations. Package delivery, preflight/partial/path fault coverage, Plugin release validation, and actual Recall Agent model consumption also require their separately bound responsibility evidence. Unknown consumers/platforms remain unknown; this script does not establish a product release.
