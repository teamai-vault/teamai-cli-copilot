# Domain docs

Use a single-context layout: `CONTEXT.md` at the repository root and ADRs under `docs/adr/`.

Before exploring a domain area, read `CONTEXT.md` and relevant ADRs when they exist. If absent, proceed without creating placeholder files. Domain documents are added when terms or decisions are actually resolved.

Use the terminology defined in `CONTEXT.md` for issues, proposals, hypotheses, and tests. If a needed term is missing, reconsider the term or record the gap for domain modeling. Surface any conflict with an existing ADR explicitly.
